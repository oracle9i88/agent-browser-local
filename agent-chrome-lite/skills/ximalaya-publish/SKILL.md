# 喜马拉雅单期发布

使用本项目的本地 HTTP/WS 或 MCP 浏览器接口。不要读取浏览器 Cookie、调用平台私有接口、写固定 CSS/XPath/坐标，亦不要用系统级点击绕过浏览器权限层。

1. 确认用户指定的音频、标题、目标专辑与简介；已在浏览器中的草稿先核实状态，不重复上传。检查 `/v1/session` 的本地 principal 是否具有 `browser.finalize.ref`。没有这项权限就准备好表单交给用户，不申请或自授权限。
2. 在 `https://studio.ximalaya.com/upload` 按当前页面截图/Snapshot 操作：选择**指定专辑**，上传一次，填标题、简介、分类、标签，按作品来源准确填写 AI 合成声明。每次写入后重新观察。分类显示灰字「音乐」不代表已选；检查必填提示和上传完成状态。
3. 发布前读回作品、专辑、分类、标签、AI 声明、文件上传状态，并截图。发现任何不确定项就暂停，不为了跑通流程猜填。
4. 调用 `POST /v1/actions/ximalaya-publish-check` 或 MCP `browser_ximalaya_publish_check`。它必须返回唯一可见的「确认发布」按钮；若返回不可用，最多在重新截图、对准嵌入页滚动一次后重查一次。仍不可用就交付诊断，不换成盲点或重复点击。
5. 在本次作品有用户发布授权且 principal 已获本地代发布权限时，调用 `POST /v1/actions/ximalaya-publish` 或 MCP `browser_ximalaya_publish` **一次**。返回 `click_dispatched_verify_publication` 只表示点击已送出，不代表发布成功。随后观察页面反馈；若有校验错误，报告具体字段并暂停，不能在同一张表单上二次点击。结果不明时绝不再点。
6. 只有在官方页面显示新单期且状态为「审核中」或「已发布」、标题/专辑一致时才报完成。否则报告“待确认”，保留最后截图及安全审计事件，不从管理列表批量采集。

操作节奏按正常人使用速度。用户接管、登录验证、授权声明或者权限不足时停在 handoff，不请求用户反复重新登录。失败后最多一次有依据的定位修正；不要耗一小时循环尝试。
